# Скиллы Мэтта Покока для ИИ-агентов

Подборка скиллов для ИИ-агента, который ведет задачу от сырой формулировки до
проверенного кода. Внутри: 5 скиллов Мэтта Покока, их зависимости и общий
оркестратор `ai-coder`, который запускает весь маршрут одной командой.

## Маршрут

```
grill-with-docs  →  to-spec  →  to-tickets  →  implement
                                                   └── code-review (сам)
```

| Скилл | Что делает |
|---|---|
| `grill-with-docs` | Допрашивает задачу раундами вопросов, по ходу пишет глоссарий и ADR |
| `to-spec` | Собирает из разговора спецификацию, без нового интервью |
| `to-tickets` | Режет спецификацию на тикеты-трассирующие пули с зависимостями |
| `implement` | Выполняет один тикет и коммитит работу |
| `code-review` | Проверяет результат по двум осям, поднимается изнутри `implement` |
| `ai-coder` | Ведет весь маршрут целиком, останавливается в трех местах |

## Что в папке

```
./
├── ai-coder/
├── grill-with-docs/
├── to-spec/
├── to-tickets/
├── implement/
└── code-review/
```

Основа взята из [github.com/mattpocock/skills](https://github.com/mattpocock/skills),
ветка `main`, коммит `bb8fdc3`, 6 августа 2026.

Этот репозиторий не является официальным релизом Мэтта Покока. Это практический
пакет под ролик: только скиллы, которые фигурируют в видео, и добавленный
`ai-coder`.

Полный набор Мэтта больше — там около тридцати скиллов. Здесь только те, что
нужны этому маршруту.

## Установка в проект

Склонируйте репозиторий и скопируйте содержимое этой папки в папку скиллов
проекта.

```bash
git clone <repo-url> skills-matt
cd skills-matt
```

Чаще всего это один из вариантов:

- `.agents/skills/` — Codex и агенты, которые читают проектные skills;
- `.claude/skills/` — Claude Code.

```bash
mkdir -p /путь/к/проекту/.agents/skills
cp -R */ /путь/к/проекту/.agents/skills/
```

Для Claude Code:

```bash
mkdir -p /путь/к/проекту/.claude/skills
cp -R */ /путь/к/проекту/.claude/skills/
```

Если ваш агент использует другую папку для скиллов, копируйте туда.

Проверка: `ai-coder` появился в списке доступных скиллов или его можно вызвать
явно через `$ai-coder`.

## Запуск

Запуск зависит от агента. Обычно это один из вариантов:

```text
$ai-coder <задача в свободной форме>
```

```text
/ai-coder <задача в свободной форме>
```

Дальше маршрут идет сам и останавливается трижды: раунды вопросов,
подтверждение спецификации, подтверждение нарезки на тикеты. После этого
тикеты выполняются без вашего участия — по одному отдельному контексту на
тикет. Если агент поддерживает сабагентов, `ai-coder` использует их. Если нет,
он работает в основном окне и просит почистить контекст между тикетами.

Если работу прервали, продолжить можно с любого места:

```text
$ai-coder дальше
```

Скиллы Мэтта можно запускать и по отдельности, если маршрут не нужен целиком.

## Два отличия от оригинала

1. **Трекер задач.** У Мэтта скиллы ждут настроенного трекера и просят сначала
   прогнать отдельную настройку трекера. В этом пакете `ai-coder` по умолчанию
   работает с локальными файлами в `.scratch/<задача>/`: спецификация в
   `spec.md`, тикеты по одному файлу в `issues/`. Если в проекте есть
   `docs/agents/issue-tracker.md`, главнее он.

2. **Тикеты выполняются сабагентами.** Правило «один тикет — одно чистое окно
   контекста» остается, но чистить контекст руками больше не надо. Главный
   агент работает диспетчером: держит спецификацию и фронтир тикетов, а на
   каждый тикет поднимает сабагента с пустым окном и отдает ему не переписку,
   а пути к спецификации и тикету. Сабагент читает их сам, делает работу,
   поднимает ревью, коммитит и возвращает короткий отчет.

   Независимые тикеты можно гнать параллельно. Тикеты, которые трогают один и
   тот же код, идут по очереди, иначе получите конфликты в рабочем дереве.

   Если у агента сабагентов нет, `ai-coder` переключается в запасной
   режим: работает в основном окне и после каждого тикета просит почистить
   контекст.

## Статус

Прогнан на учебном проекте: шаги 0-4, один тикет целиком. Работает.

Что подтвердилось на прогоне:

- сабагент выполняет тикет по `implement`, поднимает `code-review` и коммитит;
- обе оси ревью действительно запускаются параллельно **изнутри** сабагента,
  то есть вложенность в два уровня держится;
- ревью находит настоящие дефекты, а не только придирки;
- главный контекст остается чистым: обратно приходит короткий отчет, а не
  полотно.

Что вскрылось и уже учтено в пакете для сабагента:

- инструмент `Skill` внутри сабагента **не видит** скиллы проекта, поэтому в
  пакете сказано читать `SKILL.md` с диска;
- `implement` велит ревьюить до коммита, а `code-review` сравнивает коммиты —
  теперь порядок задан явно: коммит, ревью, правки вторым коммитом;
- ось Spec без ограничения читает соседние тикеты и записывает их в
  пропущенные требования — теперь ей прямо говорят проверять только текущий.

Не проверялись живьем: раунды `grill-with-docs` с настоящим человеком и
маршрут на нескольких тикетах подряд.

## Требования

Агент с поддержкой скиллов. Сабагенты желательны, но не обязательны:
`grill-with-docs` может отправлять их искать факты по проекту, `code-review`
гоняет ими две оси проверки, а `ai-coder` выполняет ими тикеты. Если сабагенты
не поднимаются, маршрут остается рабочим, но идет последовательно и требует
чистить контекст между тикетами.

`code-review` работает по `git diff` от зафиксированной точки, поэтому проект
должен быть под git.
